2026-09-25 补充：连续历史、手动固定布局、扩展按键已实现并在本地完整链路验证，尚未升级公网部署。以下第 5 节为最新交互设计，协议细节见 [协议 v1](protocol-v1.md)。

本文将 [初始设计草案](design-background.md) 落实为开发与验收方案。[README](../README.md) 提供当前运行入口。最初先完成本地交付；2026-09-24 用户提供服务器并选择不使用域名后，已部署 IP HTTPS 中转及本机常驻代理。下文保留开发设计与验收要求；实际完成状态以验证记录为准。

## 1. 目标与边界

安卓手机打开网页，登录后选择已配对电脑上的 Kitty 窗口，持续查看终端内容，发送中文文字、粘贴内容和控制按键；电脑和手机操作同一个现有进程。首版针对单用户、一台 Ubuntu 电脑、多个 Kitty 实例及窗口，主要验证 Codex CLI 与 Claude Code。

首版显示的是 Kitty 的文字快照和可获取的样式，不是桌面视频或原始 PTY 流。手机可以调字号与横向查看，但不改变电脑窗口尺寸；不要求 SSH、tmux、另起任务或通用鼠标控制。首版不提供桌面 GUI、文件管理、远程升级及端到端加密。中转服务按可信自有服务器设计，生产传输使用 TLS，服务器能够看到经过它转发的终端内容。

已先完成代码、文档、本地验收及部署配置，随后按用户提供的服务器完成部署。域名可选，公网 IP 可使用可信 HTTPS。公网与安卓真机的结果必须单独标注，不能由本地测试推断。

## 2. 已有依据和待验证项

历史记录：2026-09-23 首次在本机只读验证时，Kitty 版本为 0.48.2；现有配置启用了 socket-only 远程控制；通过 Unix Socket 成功列出一个现有窗口，并用 get-text 读取其 42 行、192 列的带 ANSI 格式屏幕快照。五次取屏耗时约 16～18 ms，仅作为当时这一个窗口的参考，不构成刷新延迟承诺。

2026-09-23 升级后确认 Kitty / kitten 为 0.49.0，前台与后台标签页均能读取 ANSI 文字快照，单次取屏约 16～17 ms。

2026-09-24 已建立应用代码、uv 虚拟环境和本地验收脚本。真实独立 Kitty 实例中的 send-text、send-key、中文与 Emoji、备用屏幕和浏览器完整链路已通过验证。Codex / Claude Code 完整任务、实际审批交互、安卓真机输入法仍待专项验收；公网链路已通过。

Kitty 0.49.0 的 screenshot 已另行只读验证可用，但用户已选择首版仅做文字；PNG 查看列为后续扩展，且受目标窗口当前可见的限制。

Kitty 官方说明 send-text 和 send-key 即使没有真正将内容送入窗口，也可能报告成功；因此本方案把“已提交至 Kitty”与“程序已收到/已执行”区分开。参见 [Kitty Remote Control 文档](https://sw.kovidgoyal.net/kitty/remote-control/)。

## 3. 架构和工程组织

~~~mermaid
flowchart LR
    B[安卓浏览器] <-->|HTTPS / WSS| R[中转服务]
    A[Ubuntu 本机代理] <-->|主动建立 WSS| R
    A <-->|用户目录内的 Unix Socket| K[Kitty 现有窗口]
    K <--> T[Codex CLI / Claude Code]
~~~

- Python 部分使用 Python 3.12、uv 和项目内 .venv，分为共享协议、Kitty 适配器、本机代理、中转服务及管理命令；提交 pyproject.toml 与 uv.lock。
- 中转采用 FastAPI、WebSocket、SQLite，单进程部署；网页采用 React、TypeScript 和 Vite，终端内容以原生滚动的网页文字行显示（2026-09-26 前为 xterm.js），构建后由同源中转服务提供。
- 提供中转 Docker Compose 与 Caddy 配置模板、本机 systemd 用户服务模板，以及安装、配对、撤销、停用说明。模板、本地验证及后续公网部署均已完成。
- 管理命令至少提供创建管理员、发起代理配对、运行代理、运行中转和诊断 Kitty 接入的入口；敏感配置放在环境或权限受限的本机配置文件中。

## 4. Kitty 接入与会话身份

首版通过 kitten 命令行客户端封装 ls、get-text、send-text、send-key、set-user-vars；每次调用使用参数数组，并设置超时。所有操作指定 Socket 和明确的正整数 window_id，不使用当前焦点作为回退目标。

代理从配置的 Socket 地址或运行目录规则发现实例，检查地址为当前用户可访问的 Unix Socket。发现窗口时只上报实例、标签页、窗口 ID、标题、必要的工作目录和尺寸；不转发 ls 中的环境变量、完整进程参数或前台进程信息。

输入目标由 device_id、agent_epoch、kitty_instance_id、window_id 标识。agent_epoch 在代理每次启动时生成；kitty_instance_id 绑定所连接 Kitty 进程及 Socket 的生命周期。代理为接管的窗口设置项目专用随机用户变量，发送输入时同时匹配 window_id 和该变量。建立标记及执行前均重新核对实例和窗口；窗口关闭、标记丢失或实例身份变化时拒绝输入。代理重启后旧目标失效，由浏览器重新获取窗口列表并订阅。

安装诊断只检查当前可接入的实例。对于尚未启用远程控制的既有 Kitty 实例，提示配置和重启条件，不自动关闭窗口或中断任务。

## 5. 屏幕、历史和手机交互

代理只采样有浏览器订阅的窗口，起始活动采样间隔为 300 ms，连续无变化后降至 2 秒；两者为初始配置值，需要测试后调整。get-text 读取当前 screen，启用 ANSI 和光标信息。快照包含目标、递增序号、采样时间、行列数、备用屏幕状态及受限格式内容；内容未变时不发送。重连和重新订阅时发送完整快照。

浏览器以收到的完整内容为准，逐行渲染为固定行高的网页文字并使用原生滚动（2026-09-26 起替代 xterm.js）；更新时只替换变化的行，不把完整快照连续追加。只保留展示所需的 ANSI 样式；过滤 OSC、剪贴板写入、外链和其他非展示控制序列，终端文字不得当作 HTML 执行。图片、复杂动画及被 TUI 覆盖的内容不作完整还原承诺。

手机布局包含窗口与连接状态、终端视图、多行输入框和按键栏。窗口选中后自动获取 Kitty 全部可读缓冲，历史独立采用 16 MiB 保护上限和自动分块，后续以带基础版本的行替换更新。滚动只访问本地内容，不触发分页或远端滚动。不区分阅读与跟随模式：停在底部时自动跟随，往上翻时新输出只替换对应行，阅读行保持不动，并提示“回到最新”。保留电脑列数与宽字符两格宽度，字号变化保持阅读行。备用屏幕程序内部未显示的历史不属于 Kitty 可读缓冲。

“固定布局”由用户手动开启并可退出，刷新后恢复普通布局。固定模式锁住外层页面，将工具栏、终端和输入区放进可视高度；通过 Visual Viewport 适配软键盘，终端内部独立滚动并阻断边界滚动传播。窗口、扩展按键及回执以抽屉显示。

输入框 Enter 默认换行；分别提供“发送文字”和“发送并回车”。组合输入期间不触发发送，手机输入法语音转文字按普通输入处理。两排常用键包括 Enter、Esc、Tab、Shift+Tab、方向键、Backspace 和 Ctrl+C，展开更多提供导航、编辑、Ctrl/Alt 快捷键及 F1–F12。触控区至少 44px；点击按键保持输入焦点。翻页键明确发送给电脑程序，与手机本地阅读滚动区分。

## 6. 中转、登录与配对

首版只有一个管理员账号，无公开注册。管理员由本机管理命令创建，密码保存为 Argon2id 哈希。浏览器采用服务端会话 Cookie；生产环境要求 HTTPS、Secure、HttpOnly、SameSite，并对写操作和 WebSocket 握手检查来源。登录失效或退出时关闭浏览器控制连接。

代理首次接入时向中转申请一次性配对码，默认 5 分钟过期。用户登录网页，输入配对码并确认设备信息。代理凭独立的高熵临时秘密领取设备凭据；配对码不能用作长期登录凭据。凭据可撤销，中转仅保存其摘要，代理本机凭据文件权限为 0600。撤销后终止该设备连接和窗口订阅。

中转只维护授权关系、设备在线状态、浏览器订阅和每窗口一个控制者的租约。其他浏览器连接可只读；控制者断开、退出或租约到期后释放控制权。每次订阅和输入都校验账号、设备、控制权及目标。只转发允许的 Kitty 操作，不提供执行任意 shell 命令的接口。持久化仅限用户、会话、设备、配对和凭据摘要，不保存终端正文；日志不记录输入、屏幕或明文令牌。

接口分组固定为 /api/auth/*、/api/pairings/*、/api/devices/*、/ws/browser 和 /ws/agent。浏览器与代理 WebSocket 使用协议版本 v1，消息类型包括窗口列表、订阅、快照、输入、回执、控制权和心跳。前端类型与 Python 协议模型保持一致。

## 7. 输入顺序、回执与断线恢复

输入请求包含 request_id、完整目标、操作类型、负载和有效期。中转将有效期限制为接收后最多 10 秒；代理在执行前再次检查。文字使用 send-text --stdin 原样传入，并采用 bracketed-paste=auto；按键只允许白名单中的 Kitty 按键名，并按请求顺序逐项发送。同一窗口输入串行执行。“发送并回车”先发送文字，初始等待 150 ms，再复核目标并发送 Enter；实际间隔通过 Codex 与 Claude Code 测试调整。文本上限 64 KiB，WebSocket 单条消息上限 1 MiB；超限直接拒绝。

| 状态 | 页面含义 |
| --- | --- |
| 待发送 | 只存在于浏览器，尚未进入连接 |
| 已接收 | 中转或代理收到请求，尚未说明 Kitty 收到 |
| 已提交至 Kitty | 代理完成了对应的 Kitty 控制调用；无法证明目标程序处理了输入 |
| 已拒绝 | 无权限、目标失效、过期、超限或重复 ID 携带不同内容 |
| 失败 | 调用前确定失败，能确认没有向 Kitty 提交 |
| 结果不确定 | 调用或回执丢失、超时、部分发送，无法确定实际副作用 |

代理在当前 agent_epoch 内对 request_id 做有界去重；同一 ID 和内容返回原回执，不再执行。相同 ID 配不同内容直接拒绝。对同一窗口按序处理，过期或队列满时拒绝；控制输入不按屏幕快照的丢弃规则处理。回执语义以 [Kitty 官方接口说明](https://sw.kovidgoyal.net/kitty/remote-control/#kitten-send-text) 为依据，不将调用成功写成“业务任务已执行”。

手机断开后终端任务继续；恢复时重新鉴权、订阅并获取完整快照。代理与中转断线时指数退避重连并报告新状态，不缓存离线输入，也不自动重发旧请求。待确认输入显示“结果不确定”，由用户看屏幕判断。慢客户端的屏幕队列仅保留最新快照，输入队列保持有界；窗口关闭时结束订阅并提示。

## 8. 实施阶段与验收

### 阶段一：可工作的本地完整链路

建立工程、协议、中转、基本登录配对、代理、Kitty 适配器和最小网页。代理主动连到本地运行的中转，由网页选择现有 Kitty 窗口，读取快照，并在专用测试窗口验证中文、粘贴和回车。该阶段必须同时包含授权、身份校验、输入去重和消息大小限制，避免后续改写协议。

通过标准：浏览器、中转、代理、Kitty 四段链路实际连通；读写严格命中目标窗口。对 Codex、Claude Code、备用屏幕、颜色、宽字符与长回复做适用性检查。如果核心阅读效果不达标，先记录缺口并修订显示方案，再继续扩展交互功能。

### 阶段二：完整手机操作

完成移动布局、窗口切换、历史阅读、底部跟随、字号、输入法组合处理、按键栏、在线状态、配对和撤销页面。在安卓浏览器上通过本地或可访问的测试环境验证“发任务、读长回复、操作选择项、中断任务、切换窗口”。没有真实设备验证时明确标记为待验。

### 阶段三：可靠性和可部署交付

补齐旧目标拒绝、断线恢复、慢网络背压、设备撤销、诊断命令、systemd 模板、Docker Compose 与 Caddy 模板、配置和安装卸载说明。后续部署已在用户提供的服务器完成。

自动化测试重点覆盖：窗口关闭或 ID 复用、代理重启、重复及过期请求、部分发送、回执丢失、无权限访问、设备撤销、中文与 Emoji 输入、全量快照替换和慢客户端队列。检查包括 pytest、Ruff、TypeScript 类型检查、前端测试与浏览器集成测试。测试中使用专用 Kitty 测试窗口，避免向用户正在执行的任务注入内容。

公网部署另列验收：HTTPS/WSS、手机流量与 Wi-Fi 切换、锁屏返回、真实输入法、长回复阅读、刷新和输入回显延迟。当前 HTTPS/WSS 公网完整链路已通过，其余安卓专项结果仍标记为待验。
